# CLAUDE.md

Guidance for working in this repository.

## Binding rules

The project's full rulebook lives in session memory (not tracked here, by policy — see
"Privacy" below). The essentials, inlined so any session has them:

### Quality bar

- PHP 8.3+ only. No PHP 5/7-era patterns, no backward-compat scaffolding — when something
  changes, update every caller.
- Fidelity first: this extension's output must be byte-identical to the upstream Lightning
  CSS CLI built from the same vendored tree. Speed work never changes output bytes.
- Nothing is "done" without: CHANGELOG entry, README sync, `docs/` updates, runnable
  self-asserting `examples/` (once subsystems exist), and tests.

### Gates (all must pass before any commit proposal)

1. `clang-format-14 --dry-run --Werror` over C sources (never on `*_arginfo.h`).
2. `cargo fmt --check` + `cargo clippy -- -D warnings` on `native/`.
3. `php -l` on the stub and all PHP files; `vendor/bin/phpcs` (PSR-12);
   `tools/phpstan.sh`.
4. Builds with `-Wall -Wextra -Werror` — zero warnings, 8.3 first, then 8.4, then 8.5
   (`tools/build.sh` enforces the order and gates each artifact).
5. `tools/elf-gates.sh build/<ver>/modules/lightningcss.so` — RELRO, BIND_NOW, non-exec
   stack, no rpath, exports exactly `get_module`.
6. `run-tests.php` per ABI (generated by phpize into `build/<ver>/`).
7. Re-run the full battery after ANY fix. Never weaken a gate to make it pass.

### Commits

- Conventional Commits, 3-block format: `type(scope): subject`, contiguous bullet block,
  optional bottom note (never `Why:`). Scopes: `lightningcss`, `ext`, `ci`, `build`,
  `installer`, `release`, `docs`, `usage`.
- Zero AI attribution anywhere.
- Only an explicit instruction containing the word "commit" authorizes a commit; proposals
  are always made first with the complete message. Tags likewise.
- Commits are local; remote operations are handled by the repository owner.

### Privacy

- This repository is public. Private planning, design, and review records live in
  the project root, stay untracked, and their names are listed in
  `.git/info/exclude` — never in `.gitignore`, never referenced from tracked
  files, never staged.
- `docs/` holds shipped product manuals only; never plans.
- No phase/milestone identifiers, no competitive analysis, no private paths in tracked
  content.

### Reviews

The advisor gate is: external review before any commit proposal — via the advisor tool
when available, otherwise a flat review agent (must not spawn subagents; static read-only)
or the owner's own review. Review verdicts authorize folding fixes immediately.

### Vendored upstream

Upstream Lightning CSS is pinned (exact release + SHA-256) in `vendor-src/` (gitignored).
Bumps go through the drill: changelog + security advisories first, then pin + hash +
`php_lightningcss.h` together, full re-gate after.
